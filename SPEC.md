## 2. Functional Requirements

### 2.1 Class Management
- Admin can create a class with its name, shift, and seat capacity.
- Display all classes and their seat availability.
- Each class/shift must maintain its own seat capacity.
- Show held, confirmed, and available seat counts.

### 2.2 Admission Application
- A student is identified by their birth registration number (`Student ID`).
- A student can apply for a class/shift.
- Applying temporarily holds one seat for that student.
- The hold has a configurable expiration period.
- If the admission fee is paid within the hold period, the application becomes confirmed.
- If the hold expires or is cancelled, the seat becomes available to other students.
- A student can have only one active or confirmed application per class.

### 2.3 Application Management
- Students can view their own applications.
- Application details must include class information, status, and expiration time.
- Students can confirm an unexpired application by clicking **Pay Admission Fee**.
- Students can cancel their own active application.
- Payment is simulated: clicking the payment action is considered successful.
- Students must be able to see application status after refreshing or reopening the browser.

### 2.4 Application Statuses

- `HELD` — Seat temporarily reserved.
- `CONFIRMED` — Admission confirmed.
- `EXPIRED` — Hold expired without confirmation.
- `CANCELLED` — Application cancelled.

### 2.5 Required UI
- Class creation form for admins.
- Class listing with held, confirmed, and available seat counts.
- Application details with expiration countdown/status.
- Pay Admission Fee and Cancel actions.
- My Applications page.
- Clear validation and error messages.
- Automatically reflect expired status and disable payment without requiring a page reload.
- Refresh seat counts every few seconds.

## 3. Required API

Backend must expose these endpoints:

| Method | Endpoint | Purpose |
|---|---|---|
| POST | `/classes` | Create a class |
| GET | `/classes` | List all classes |
| GET | `/classes/{classId}` | Get class details and seat counts |
| POST | `/classes/{classId}/holds` | Create a seat hold |
| GET | `/holds/{holdId}` | Get hold details and status |
| POST | `/holds/{holdId}/confirm` | Confirm admission |
| DELETE | `/holds/{holdId}` | Cancel a hold |
| GET | `/me/holds` | List the current student's applications |

**API requirements:**
- Use `X-Student-Id` to identify the student for student-specific operations.
- Return `409 Conflict` when no seats are available.
- Return `204 No Content` when cancellation succeeds.
- Use the status values defined above.
- Follow the request/response JSON structures specified in the assignment.

## 4. Non-Functional Requirements

### 4.1 Concurrency and Data Integrity
- Multiple users may apply simultaneously.
- Seat capacity must never be exceeded.
- Concurrent requests must not reserve the same final seat.
- Held and confirmed seats together must never exceed total capacity.
- The implementation must remain safe when multiple backend instances run against the same database.

### 4.2 Persistence
- Classes and applications must persist in PostgreSQL.
- Data must survive `docker compose down` followed by `docker compose up`.
- Browser refreshes and reopening must not lose a student's applications.

### 4.3 Reliability and Error Handling
- Invalid input must return appropriate 4xx responses, not 500 errors.
- Handle expired holds, unavailable seats, invalid requests, and server errors.
- Display understandable errors in the UI; console-only errors are insufficient.

### 4.4 Configuration
- Hold duration must be configurable through `HOLD_DURATION_SECONDS`.
- Default hold duration: `600` seconds.
- Database connection must be configurable through environment variables.
- Frontend backend URL must be configurable through an environment variable.

## 5. Technical Constraints

- Backend: C# with .NET 8 or newer.
- Database: PostgreSQL.
- ORM: Developer's choice.
- Frontend: React 18 or newer, JavaScript or TypeScript.
- Vite is recommended for frontend setup.
- Backend must run at `http://localhost:8080`.
- Frontend and backend must communicate through the API.
- All admin and student operations must be accessible through the UI.
- The complete project must run using Docker Compose.
